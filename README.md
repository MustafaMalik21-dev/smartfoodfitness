# SmartFoodFitness — Backend API

A Spring Boot REST API powering a food and fitness tracking app, with AI-generated meal and workout recommendations from Claude.

📱 Mobile app: [smartfoodfitness-mobile](https://github.com/MustafaMalik21-dev/smartfoodfitness-mobile)

## ✨ Features

- **Nutrition tracking** — log meals and track macros, with food data from the USDA FoodData Central API
- **Workout tracking** — log workouts and progress, with an exercise library from the Wger API, mapped to muscle groups (chest, back, legs and more)
- **AI recommendations** — personalised meal and workout suggestions generated by Claude (Anthropic API) from each user's logged macros and training history
- **Secure authentication** — JWT-based login and protected endpoints
- **~50 REST endpoints** backed by a 15-table PostgreSQL schema

## 🛠️ Tech Stack

| Layer | Technology |
|---|---|
| Language & framework | Java, Spring Boot |
| Database | PostgreSQL (Spring Data JPA / Hibernate) |
| Auth | JWT |
| External APIs | Anthropic Claude, USDA FoodData Central, Wger |
| Deployment | Railway |

## 🏗️ Architecture

The React Native mobile app communicates only with this backend. All third-party API keys, including the Claude key, are held server-side as environment variables and never shipped in the app.

## 🚀 Running Locally

1. Clone the repo and create a local PostgreSQL database
2. Create `src/main/resources/application-local.properties` with your database credentials
3. Set the required environment variables:

| Variable | Purpose |
|---|---|
| `APP_JWT_SECRET` | Signing secret for JWT tokens |
| `ANTHROPIC_API_KEY` | Claude API key for recommendations |
| `USDA_API_KEY` | USDA FoodData Central key |
| `WGER_API_KEY` | Wger exercise API key |

4. Run the app:
   ./mvnw spring-boot:run -Dspring-boot.run.profiles=local

The API starts on `http://localhost:8080`.

## 📚 What I Learned

- Designing a relational schema where meals, macros and workouts all relate to each user over time
- Integrating several third-party APIs and keeping secrets out of source control
- Deploying within tight resource limits (Railway's 512 MB cap), using lazy initialisation to cut memory use
